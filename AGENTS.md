# AGENTS.md

Инструкции для агентов, работающих в репозитории `kb`. Обзор проекта — в `README.md`.

## Как тестировать

- **Полная проверка:** `scripts/check.sh` из корня репозитория. Это та же команда,
  что и проверка задачи. Скрипт запускает только существующие части: без
  `Cargo.toml` он сообщает, что проверять нечего, и выходит с кодом 0. С workspace —
  `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo test --workspace --locked`, а при наличии `crates/kb/tests/budget.rs` —
  бюджетный тест горячего пути в release.
- **Быстрый прогон:** `cargo test -p <crate>` для одного крейта, например
  `cargo test -p kb`. Отдельный тест — `cargo test -p <crate> <имя_теста>`.
- **Toolchain:** закреплён в `rust-toolchain.toml` (1.99.0, компоненты `rustfmt` и
  `clippy`); rustup подхватывает его сам. Не меняйте версию и не вызывайте
  `cargo +<другой toolchain>`. Если toolchain не установлен, не ставьте его сами —
  сообщите владельцу.
- **Подготовка окружения:** не нужна. Сеть, `.env` и внешние сервисы тестам не нужны;
  `target/` создаётся при первом прогоне и в git не попадает.
- **Нельзя в тестах и проверках:** ставить kb на машину (`kb setup`) и вызывать
  `kb remember` / `kb propose` — это делает только владелец.

Если позже `kb init` добавит в этот файл управляемый блок, раздел «Как тестировать»
остаётся вне него.
